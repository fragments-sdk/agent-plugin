---
name: check-react-ui
description: Inspect and check saved React UI with the local Fragments engine, including Next.js, Vite, TanStack Start and React Router projects. Use for Fragments static design-system checks; browser rendering and screenshot inspection require separate tools.
---

Use this plugin's `contract` and `design_system` tools to inspect the selected project's saved policy, components and tokens. Installing this plugin globally does not initialize projects or select Fragments UI. Detected components are suggestions from the project's files; saved component rules and the user's instructions govern their use. Preserve the user's React framework, UI library and existing component APIs. If the project has no readable components or tokens, continue the user's task without inventing a design system or installing a library. Adopt a library only when the user or project instructions call for it. General design foundations are optional guidance, not adopted project rules.

When hooks run, Fragments checks edits and reports what they added. Only an explicit strict contract may hold a plugin turn for new drift; projects without one receive advisory feedback. Treat those suggestions within the user's requested scope, not as required repairs. Hook activity in an earlier connection does not establish coverage now. If current hook feedback does not establish that your edits were checked, call `check` on the edited files before handing back. Silence alone is not a pass. Also check files the person changed. Report execution state, contract verdict and material coverage limits; the check's verdict is distinct from permission to enforce it. An incomplete result is not a pass, and a file-scoped check does not establish a whole-project verdict. A result beginning "For the person:" contains a setup or coverage limit: pass its words to the person and check your own edits when automatic coverage is unavailable.

Use a finding's stable `key` and the returned `reportId` with `explain`. A stale-report response means the source or policy changed: check again before interpreting that finding. These tools read current files; they do not retain a prior source snapshot.

Contract setup is optional and user-initiated. Do not offer or start setup just because a project has no contract. When the person asks to review or edit the contract, call `contract_review`: compatible hosts can show an interactive review; terminals receive the same project state as text. This view is for contract settings, not the project's rendered UI. When the person asks to approve tokens or components, set the spacing scale, or add the design check to CI (`part: "check"`, `ci: true`), use `contract_propose` and show every file it writes and what it adds. In the interactive view, selections stay local until the person chooses Review changes. The panel shows exact file changes; its Save changes button confirms that reviewed proposal. Undo has a separate confirmation. These app-only actions retain the host's tool permissions; never call their private tools on the person's behalf or invent a confirmation token. In text-only sessions, `contract_save` with the proposal digest still asks in the host's dialog and writes only on acceptance. If that dialog is unavailable or declined, report the limitation without substituting another write path or changing host settings. Saved local rules take effect immediately; nothing is committed. `contract_undo` takes the project's last save back while its files remain unchanged; name the app and files it affects. After a save, undo or uncertain outcome, read `contract_review` again before reporting the current state. The tools do not accept drift, render project pages or make screenshots. Edit source through the coding host's usual tools within the user's request. The Fragments app is optional; what it pictures is separate from this static check.

If the check reports a configuration from the older Fragments CLI or Cloud, keep it and report the limit the check names. Do not replace it, infer a second policy, call another engine as a silent fallback, or switch frameworks to obtain a pass. If the tools fail or are missing, say so: a failure does not authorize downloading another version or calling a hosted service.
